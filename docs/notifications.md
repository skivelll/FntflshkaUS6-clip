# Уведомления и технические отчёты

Desktop phase7, Windows native. Firmware, protocol, assets, partitions and upload
commit remain unchanged. All serial/file/image work stays in the existing workers.

Ошибки подключения, подготовки изображения, чтения preview, загрузки, операций
со сценами, библиотеки, восстановления и плейлиста передаются как structured
Problem. Сохраняются исходный тип/сообщение исключения и цепочка причин; прежние
строковые сигналы оставлены для совместимости статуса и существующих tests.

## Что видит пользователь

- Отдельное окно: короткий заголовок, простое объяснение, следующий шаг и состояние
  операции. «Понятно» только закрывает уведомление и не повторяет запись.
- «? Подробнее» раскрывает read-only технический отчёт; «Скопировать отчёт»
  показывает его и копирует в clipboard по явному нажатию. Отправки по сети нет.
- Заметная кнопка последнего сообщения остаётся в основном окне для повторного
  просмотра. Различные ошибки ждут прочтения в очереди; одинаковая ошибка
  подключения не всплывает на каждом polling tick. Очередь ограничена16 записями;
  при переполнении показывается сводка дополнительных ошибок и путь к журналу.
- «Звук ошибок» выключен по умолчанию, включается пользователем и сохраняется
  в локальных preferences. Визуальное сообщение работает независимо от звука.
- Ожидаемые ограничения при настройке GIF, памяти и плана восстановления остаются
  явно рядом с полями, с кнопкой «Почему?». Изменение диапазона/ползунка не создаёт
  поток всплывающих окон. Недопустимая запись остаётся заблокированной.

Окно использует show(), а не блокирующий exec(): Qt event loop и worker threads
продолжают работать. При ошибке внутри модального диалога уведомление доступно
поверх него; закрытие временного родителя не теряет непрочитанное сообщение.

## Честное состояние операции

Не считать timeout доказательством неуспешного commit. Если полный результат
не подтверждён, предложить проверку списка сцен/настроек после подключения.
Не повторять upload/delete/rename/reorder/restore автоматически.

Если upload уже вернул проверенный результат, а последующий preload завершился
ошибкой, сообщить, что запись подтверждена и повторять её не нужно. RestoreFailure
показывает подтверждённые ID и последний непроверенный шаг. Чтение и local image
preparation явно не меняют содержимое платы. Ошибка сохранения preferences
показывается перед закрытием, без бесконечных повторных попыток записи настроек.

## Отчёт для разработчика

UTC, OS/Python/PySide, portable build metadata (когда доступны), операция,
исходное исключение/traceback и exception chain; NACK code, command/sequence,
последний запрос и ACK, известный USB identity/firmware/capabilities/storage,
metadata сцен/CRC и размеры исходящего header по ситуации. Неизвестные данные
помечаются отсутствующими, а не выдумываются.

Отчёт не читает runtime logs, не содержит pixels/asset bytes, environment dump
или секреты. Binary context заменяется длиной; домашняя папка заменяется <HOME>.
Нужные для IO диагностики имена файлов/папок видимы в подробностях. Report<=64KiB,
traceback<=16KiB, строки/структуры context ограничены. Основная причина стоит
до больших snapshots, поэтому усечение не скрывает её. Runtime logs остаются
в user-data directory, demo и реальные настройки разделены.

## Проверка

После успешного восстановления подключения нижнее предупреждение об отключении
скрывается. Повторная попытка подключения сама по себе его не скрывает; ошибки
записи с неизвестным результатом сохраняются даже после восстановления USB.
Технический отчёт последней ошибки остаётся в Notifications и runtime-журнале.

Unit tests: friendly NACK + исходный technical context, partial restore IDs,
disk-full/port-busy/exception chains, binary redaction, copy without touching the
real clipboard, живой Qt timer, dedup/recovery, unread queue, transient-parent
lifetime, stale render rejection, sound preferences, settings-save failure,
mock upload без USB/automatic retry, post-commit failure и archive/image workers.
Bundled smoke дополнительно проверяет окно/подробности/очередь на protocol mock.
138 desktop +9 tools tests прошли. Основная portable-сборка в desktop/dist пересобрана и прошла извлечение/SHA256/isolated environment и 19 bundled mock checks. Read-only проверка платы COM3 с firmware 1.8 прошла: обе сцены прочитаны и проверены, повторное подключение не вызвало повторного чтения assets; content_mutated=false. Пользовательская проверка уведомления при физическом отключении USB, подробностей и восстановления подключения ожидается.
