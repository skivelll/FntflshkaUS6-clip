# Текстовые слои и бегущий текст

Фаза 9 работает на desktop с установленной firmware 1.8. Firmware, LCD driver,
Flash/partitions, protocol v1 и asset v1 не меняются. Шрифты растеризуются Qt
на компьютере в ImageWorker; на плате нет TTF/OTF renderer.

## Создание и редактирование

Слева «+ текстовая сцена» создаёт прозрачный локальный исходник поверх выбранного
фона. Можно также добавить обычную картинку и открыть справа «Текст и движение».
Для сохранённой static сцены сначала нажать «Редактировать…»: её проверенный
RGB565 остаётся неизменным исходником, новый текст добавляется сверху. Старый
запечённый текст не распознаётся и не превращается в редактируемый слой.
Текст поверх импортированного GIF/прочитанной анимации пока не поддерживается;
обычный GIF pipeline сохраняется. Новую текстовую сцену можно создать независимо
от выбранной сцены/GIF, без изменений на плате.

До 8 слоёв, до 512 символов в каждом, русский и латинский текст. Параметры:
установленный шрифт, размер 8–96 px, цвет, координаты, ширина переноса 16–320 px,
выравнивание слева/центр/справа, обводка 0–3 px с цветом, необязательная подложка.
Перенос по символам предсказуемо ограничивает ширину; экран обрезает выходящие
области. Растеризуемая поверхность слоя ограничена 326×172; длинный текст не
создаёт неограниченную bitmap. Отсутствующий шрифт даёт явную ошибку, его нужно
выбрать заново. Шрифты в проект не встраиваются.

Во вкладке текста drag в preview двигает выбранный слой, колесо меняет размер
шрифта; во вкладке изображения gestures продолжают управлять изображением.
↑/↓ меняют порядок наложения (нижняя запись рисуется последней/сверху), удаление
убирает только локальный слой. Undo/redo сохраняет до 100 шагов слоёв и движения.
Числовые поля имеют отдельные ▼/▲, сохраняя ввод числом. Изменения сразу
пересчитываются в worker; upload доступен только для последнего готового состояния.

Статичный текст растеризуется после обработки изображения, перед RGB565.
Preview декодирует точный outgoing asset v1. «До / после» сравнивает обработку
изображения с одинаковыми текстовыми слоями. Добавление/редактирование не пишет
на плату; новый upload выбирает свободный ID, замена существующего ID требует
прежнего подтверждения и проверки USB identity/checksum через A/B commit.

## Движение

Режимы: статичный, справа налево, слева направо. Движется вся группа слоёв;
исходное изображение остаётся неподвижным. Скорость 10–120 px/s, дополнительная
пауза без текста 0–2000 ms один раз за цикл. Начальный и конечный кадры не
содержат текста: шов цикла не перескакивает через видимый текст, фон сохраняется.
GUI начинает preview с проверенного кадра около заданного положения, чтобы
текст был виден при редактировании; это та же последовательность с другой фазой.

Это конечная зацикленная animation type2, существующий encoding1 RLE/delta
(либо encoding0, если encoder определит его меньшим). Используются прежние
duration floors: полный 320×172 — 350 ms/кадр, до ~2,9 кадров/с; LCD может быть
медленнее. Более высокая плавность не обещается. Конечная последовательность
не обрезается автоматически. Длительность/FPS/фактический размер показываются
после подготовки; точное превышение файла 820 KiB даёт явную ошибку. Проверяются
32 MP expanded preview и фактический library/free-space preflight при upload.
На старой firmware без compression запись encoding1 блокируется до USB writes.

Воспроизведение использует уже существующую firmware-анимацию: автономно без
desktop, после RESET из LittleFS. Подтверждение на реальном LCD/RESET обязательно
отдельно от mock/build.

## Проекты

`.fclipimage` version2 сохраняет RGBA source, обработку, слои и параметры движения
в двух ZIP entries; новые version3 добавляют отдельный drawing.png. Version1
читается как проект без текста, version2 — без рисунка. JSON ограничен
32 KiB, проект/распакованный ZIP — 64 MiB, исходник — 40 MP; новые поля строго
проверяются, пути ZIP не извлекаются. Атомарное сохранение через временный файл
сохраняет предыдущий проект при ошибке. Preferences/автоматический RAM cache/
`.fclip` коллекции не превращаются в хранилище редактируемых текстовых слоёв.
Проект нужно сохранить явно; чтение готовой сцены с платы восстанавливает только
пиксели. Импорт проекта создаёт новый локальный draft без автоматической замены ID.

## Проверки

Тесты: кириллица/латиница, CRC/точный RGB565, неизменный исходник, порядок/обводка/
подложка/crop, два направления и одинаковые крайние кадры цикла, лимиты/неизвестный
шрифт, проекты v1/v2, GUI undo/redo/drag/создание без USB. Bundled smoke проверяет
static и scroll uploads с ACK/ACTIVE/cache на protocol mock, без реального USB.
Пользователь подтвердил корректность UI, проектов, LCD и RESET; затем сообщил
о рывках preview и торможении при перемещении текста. Исправление интерактивного
preview подтверждено пользователем: перетаскивание работает отзывчиво.

Windows validation: 154 desktop +9 tools tests прошли; portable ZIP прошёл
SHA256/извлечение/изолированное окружение и 24 bundled smoke checks без USB.
Native firmware host tests в этой desktop-фазе не запускались: firmware не менялась.

## Быстрое редактирование

Во время изменений бегущего текста ImageWorker готовит только статичное положение
слоёв, используя один кэш обработанного фона. Анимация пересобирается после
300 ms без изменений, не во время удержания drag. Промежуточный preview явно
помечен как редактирование и никогда не становится uploadable asset; запись
разрешается только после полного последнего render. Проект можно сохранить
независимо от готовности/вместимости анимационного файла, если его данные валидны.

Preview воспроизводит исходные durations точным Qt timer с monotonic deadlines,
без накопления задержки на обработку каждого кадра. После длительной задержки
event loop пропускает просроченные кадры, оставаясь в реальном времени; скрытое
окно приостанавливается. Искусственные промежуточные кадры не добавляются.
Частота полного encoded текста остаётся 350 ms/кадр, ~2,9 FPS. Это ограничение
текущего animation pipeline, а не стоимость показа QImage (~0,1 ms в замере).
Замер 100 быстрых renders: median 4,81 ms, max 6,87 ms на текущей машине;
это измерение, а не гарантия для всех изображений/шрифтов.

Повторная проверка после оптимизации: 157 desktop +9 tools tests завершились
с итоговым OK и exit code 0; GUI-тест активации/удаления отдельно прошёл трижды.
Portable verification/SHA256/изолированное окружение прошли. Прежний обрыв
полного прогона не воспроизвёлся; его причина не установлена. Firmware host
tests недоступны: нативный GCC/Clang на машине отсутствует.
