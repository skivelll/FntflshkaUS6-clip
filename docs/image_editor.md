# Интерактивный редактор сцен

Firmware 1.2, USB protocol v1, asset v1, Flash и LittleFS layout не меняются.

## Положение и масштаб

После импорта PNG/JPEG/WEBP тяни изображение левой кнопкой внутри рамки preview.
Расстояние мыши пересчитывается в пиксели LCD, X/Y справа синхронизируются.
Перетаскивание начинается только внутри экрана; за его границей можно продолжить
уже начатый drag. Сдвиги ограничены текущим диапазоном −640…640 px.

Масштаб задаётся ползунком или числом 10–400%. Ввод числа применяется по Enter
или при уходе фокуса. Колесо над экраном меняет масштаб примерно на 10% от
текущего значения за шаг, сохраняя точку под курсором с округлением X/Y до пикселя.
Вне экрана колесо не меняет изображение. Во время USB-операций управление блокируется.
Расчёт RGB565 остаётся в image worker; UI не ждёт serial. События объединяются
таймером 33 ms без постоянного переноса срока. Во время непрерывного жеста
показываются промежуточные RGB565-кадры текущего источника, а upload разрешается
только для последнего законченного состояния. Одновременно считается один кадр;
смена/отмена источника запрещает показ его устаревших результатов.

## Уже загруженные сцены

Выбери сцену и нажми «Редактировать сцену…». Приложение использует уже проверенный
asset из RAM: никаких повторных READ_SCENE по выбору/входу в редактор.
Начальный масштаб 100% совпадает с текущей картинкой LCD, включая центрирование
маленьких assets. Источник редактора неизменяемый: каждое движение считается от
одних и тех же пикселей, а не от предыдущего preview.

Важно: на плате сохранён итоговый RGB565, включая ранее добавленный фон и обрезку.
Оригинальные PNG, прозрачность и обрезанные части не хранятся. Масштабирование
такой сцены работает с сохранённой картинкой целиком. Для восстановления исходного
кадра используй «Заменить картинку…» и оригинальный файл.

Изменения до «СОХРАНИТЬ СЦЕНУ N» существуют только в preview. Сохранение требует
подтверждения (отмена по умолчанию), проверяет порт/USB identity/старый checksum
и использует существующий безопасный A/B upload того же ID. Имя и порядок
сохраняются, ACK/checksum/ACTIVE/storage проверяются как при обычной замене.
Другие сцены не перезаписываются. «Отменить изменения» удаляет draft без записи
на плату. Специальные настройки текущего редактирования сцены не перезаписывают
обычные настройки импорта при закрытии приложения.

Редактор формирует полный asset размером экрана: 110104 bytes для 320×172.
Для маленького старого asset файл после редактирования может стать больше,
даже если визуальное размещение не менялось. Старый A/B-файл остаётся;
свободное место под новую запись требуется до commit.

## Полоса памяти

- Серый — фактически занятые bytes по GET_STORAGE; тёмный — свободные.
- Розовый — размер подготовленного файла в свободной части; красный означает,
  что места с обязательным запасом 8192 bytes недостаточно.
- При выборе сохранённой сцены бирюзовый — текущий файл, который будет удалён.
  Отдельно показан приблизительный будущий free, а не обещание точного результата.

Размер файла известен точно (`24 + width × height × 2`). Но current v1 API
не сообщает размер старого A/B slot, фактически выделенные блоки/metadata LittleFS
и эффект удаления manifest record. Поэтому оценка удаления не равна точному
количеству освобождаемых блоков. После ACK показывается фактическое изменение free.
В forecast замены нельзя вычитать старую сцену: файл сохраняется для upload safety.

## Проверки

Автотесты проверяют drag после resize, числовой ввод/колесо/anchor, блокировки,
точность исходных RGB565, cancel и stale identity/checksum, сохранение ID/title/order
через worker и отсутствие повторных reads. Полоса проверяется и по модели bytes,
и по фактически нарисованным цветам. LCD и реальные жесты подтверждаются отдельно
на portable сборке; результат будет дописан после проверки.

Проверено 2026-10-15 на Windows 11 / Python 3.12.10:

- 64 desktop tests + 8 tools tests: PASS, включая обновления до отпускания ЛКМ
  и во время непрерывного wheel stream с искусственно замедленным worker.
  Старые кадры при смене источника не показываются; очередь render ограничена.
- RGB565 encode/decode переведены с Python pixel loops на native Pillow band
  operations, без новых зависимостей и без изменения формата. Проверены все
  65536 RGB565 значений и границы RGB888 каналов против scalar codec: byte parity PASS.
  Средняя подготовка 320×172 кадра на этой машине: 202.6 → 21.5 ms.
- Native Windows source smoke: жесты, числовой масштаб, RAM editor и безопасное
  сохранение того же ID прошли; asset reads в mock-сценарии — 0.
- `pip check`, `compileall`, `git diff --check`: PASS.
- Перед проверкой на плате: firmware 1.2 / COM3 / `303a:1001`, семь сцен ID 1–7,
  порядок `2,1,3,4,5,6,7`, ACTIVE 7, LittleFS total/free `2031616/1204224`.
  Исходные CRC и порядок только прочитаны; сцены пользователя не заменялись.
- Firmware, vendor driver, protocol/asset format, partition layout и зависимости
  runtime не менялись. C host tests не выполнялись (native C11 compiler отсутствует).
- Portable ZIP после live-preview fix: 52,821,774 bytes; exe SHA256
  `bde58957a40b1102caf0f857a8ee2a91062afa1d953c1f09ab259a2ec3b84b37`.
- Проверка распакованного ZIP вне repo, с Unicode-путём и без Python в PATH:
  10 native Windows smoke checks PASS за 3.188 s, 91 event-loop ticks,
  0 asset reads в mock. Screenshot редактора проверен.
- Реальная плата через первую portable сборку редактора: read-only PASS за 60.250 s,
  7 assets прочитаны при старте; после выбора previews и программного reconnect
  число чтений осталось 7. CRC, порядок, ACTIVE и LittleFS free не изменились.
- Пользователь подтвердил сохранение редактирования на заколке и совпадение
  результата с LCD. Выявленное откладывание preview до конца жеста исправлено:
  таймер больше не перезапускается каждым событием, промежуточные кадры текущего
  источника показываются до окончания жеста, RGB565 conversion ускорена.
  Пользователь повторно проверил обновлённую portable сборку и подтвердил:
  preview движется при удерживаемой ЛКМ и масштабируется во время вращения колеса,
  без ожидания окончания жеста. Физическая проверка редактора завершена.
- После пользовательского сохранения: изменена сцена 5, CRC `2098eb6a`,
  файл `scenes/0005b.bin`, ACTIVE 5; порядок `2,1,3,4,5,6,7` и CRC остальных
  сцен сохранены. LittleFS total/free `2031616/1093632`.
