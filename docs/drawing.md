# Рисование пикселями

«+ нарисовать» слева создаёт новую сцену. Можно также открыть статичную картинку
или нажать «Редактировать…» для static сцены на плате, затем выбрать «Рисунок».
Рисунок — отдельный прозрачный RGBA слой в координатах LCD 320×172, поверх
изображения и текста. Исходник не меняется; старый рисунок, запечённый в RGB565
на плате, не может автоматически стать отдельным слоем.

Инструменты: карандаш 1–16 px без сглаживания, ластик прозрачности слоя,
заливка слоя, пипетка из точного RGB565 preview, палитра и выбор цвета.
Заливка ищет области только в рисунке, не в фотографии под ним. Это явно
указано в интерфейсе. Ластик не уничтожает исходную картинку или текст.
Очистка требует подтверждения с отменой по умолчанию и сохраняется в undo.
До 50 шагов undo/redo: один завершённый штрих или заливка — один шаг; история
не растёт на каждое движение курсора. Максимум около 11 MiB RGBA snapshots.

В режиме рисования ЛКМ рисует, колесо меняет zoom preview (1/2/4/8×), средняя
кнопка перемещает вид. Эти gestures не меняют масштаб/сдвиг картинки на LCD.
Координаты вычисляются через актуальный display rectangle, поэтому размер окна
и Windows DPI не задают другие пиксели. Сетка показывается при размере клетки
от 8 экранных единиц; она не попадает в outgoing asset. Кнопка возврата вида
центрирует холст. В других вкладках сохраняются прежние gestures картинки/текста.

UI рисует bounded штрихи на локальном слое; подготовка итогового RGB565 идёт
в ImageWorker с одной render-задачей и кэшированным обработанным фоном.
Заливка выполняется в worker, результат проверяет source revision и revision
слоя; устаревший ответ не перезаписывает новое состояние. Во время заливки
upload/save project блокируются. Во время штриха preview продолжает обновляться;
для движущегося текста полная анимация ждёт завершения жеста и idle.

## Сохранение

Итог статичной сцены — прежний static RGB565 asset v1; firmware, protocol,
LCD driver и partition layout не меняются. Загрузка в свободный ID либо
подтверждённая замена идут через прежний A/B commit, CRC/ACK/ACTIVE/storage.
Если отдельно включено движение текста, рисунок остаётся неподвижным верхним
слоем каждого кадра прежней type2 анимации; GIF не модифицируется этой фазой.

`.fclipimage` version3 хранит `source.png`, `settings.json`, `drawing.png`.
Параметры обработки/текста остаются в JSON, рисунок — отдельный PNG. Version1/2
с двумя entries читаются без рисунка. ZIP paths не извлекаются; проверяются
точный состав/version, CRC ZIP, JSON ≤32 KiB, суммарный размер ≤64 MiB,
source ≤40 MP и drawing PNG ровно размера логического LCD (entry ≤1 MiB).
Несовпадение размера рисунка с устройством не приводит к автоматическому
обрезанию: GUI сообщает ошибку. Сохранение атомарное, через временный файл.
Проект сохраняется явно; preferences/USB cache/.fclip коллекции не заменяют его.

## Проверки

Автотесты проверяют непрерывный штрих, ластик, undo/redo/лимит истории, заливку
и её границы, независимость исходника, наложение поверх текста, точный RGB565,
координаты при zoom, реальный Qt mouse click, отмену очистки, cache reuse,
отбрасывание устаревшей заливки и проекты version3/неверный размер PNG.
Mock smoke: штрих, асинхронная заливка, project roundtrip и upload ACK/ACTIVE
без реального USB. LCD и hardware RESET требуют физического подтверждения.

При полном GUI-прогоне обнаружен Windows/Qt access violation при создании
очередного окна. Завершение потоков усилено: stop до deleteLater, nonblocking
wait(0) перед принятием close; добавлен lifecycle regression. После этого полный
прогон 164 desktop tests прошёл. Первый стресс-процесс завис и был остановлен;
повторный диагностический прогон с ограничением времени прошёл все 32 цикла
создания/закрытия/удаления окон с реальными Qt workers. Точная причина исходных
нативных сбоев не доказана; эти проверки нужно сохранять, не считать обрыв
журнала успешным тестом.

Финальная Windows validation: два последовательных полных прогона по 164 desktop
tests завершились OK/exit 0, отдельно 9 tools tests — OK. Portable ZIP прошёл
SHA256/извлечение/изолированное окружение и 28 mock smoke checks, без USB.
Firmware host tests в этой desktop-фазе не запускались; нативного GCC/Clang нет,
firmware не менялась. Пользователь подтвердил работу инструментов, сохранение и
повторное открытие проекта, совпадение LCD с preview и сохранность после RESET.
Выбор инструмента показывает нарисованные значки карандаша, ластика, заливки и
пипетки рядом с названиями, включая текущий выбранный инструмент.

После добавления значков полный прогон один раз дал несовпадение пикселя в
test_drag_uses_lcd_pixels_and_works_after_window_resize при верных координатах.
Отдельные 13 editor tests и повторные 164 desktop tests прошли без изменений
логики редактора; причина единичного сбоя не подтверждена. Также прошли 9 tools
tests и portable smoke/ZIP validation. Сбой сохранён в журнале проверки,
не считается исправленным только на основании повторного успешного прогона.
