# Автономный плейлист статичных сцен

Firmware 1.3 добавляет optional команды плейлиста protocol v1; firmware 1.4 —
выбор перехода. Asset v1, LCD driver, Flash 4 MB и partition layout сохранены.
GUI проверяет capability bit 2 для плейлиста и bit 3 для переходов.

Открой «Плейлист…», отметь сцены, выставь порядок стрелками и общий интервал
1–86400 секунд. Включи переключение и явно сохрани настройки. Запись
подтверждается ACK и чтением обратно. Приложение можно закрыть: таймер работает
на ESP32. После RESET включённый плейлист начинает с первой доступной валидной
сцены; текущая позиция таймера не сохраняется.

Интервал и переход скрыты, пока галочка переключения снята. Интервал можно
ввести числом, увеличить/уменьшить отдельными кнопками ▲/▼ (удержание повторяет
шаг). Миниатюры возле ID/имени берутся из проверенного RAM-кэша без новых USB reads.

Переходы: обычная смена, раскрытие слева направо/справа налево/сверху вниз/снизу
вверх и раскрытие из центра. Интервал отсчитывается после завершения перехода.
Раскрытие постепенно заменяет область старого кадра
новой; само изображение не перемещается. Целевое время 400 мс, медленное чтение
может удлинить его. Обычная смена гасит подсветку на время strip отрисовки:
короткая тёмная пауза скрывает проход сверху вниз. Это не double-buffer swap.
Все режимы сохраняют DMA-буфер 5120 байт; узкие tiles используют дополнительно
640 байт row scratch на стеке, без full-screen framebuffer; vendor
driver не менялся. Переход выполняется в основном цикле; USB ждёт его завершения.

Чтобы остановить, сними галочку и сохрани. Ручной показ, UPLOAD_BEGIN и
DELETE_SCENE также останавливают плейлист до операции и сохраняют отключённое
состояние (включая старый CLI). Даже неудачная операция может оставить режим
остановленным; автоматически он не возобновляется. Переименование и порядок
обычного списка сцен не меняют порядок плейлиста.

Настройки содержат ID. Замена картинки по тому же ID заменяет её и в плейлисте,
но upload останавливает воспроизведение. Отсутствующие/повреждённые сцены
пропускаются. Отсутствующий ID снова участвует при создании новой сцены с этим
ID; GUI исключает отсутствующие ID при следующем сохранении плана. При отсутствии
пригодных сцен остаётся текущий экран/штатный fallback. Один пригодный ID остаётся
на экране без повторной отрисовки по таймеру.

Экспорт .fclip работает во время воспроизведения; ACTIVE фиксируется при снимке
списка. Архив v1 содержит сцены, но не настройки плейлиста. Перед восстановлением
коллекции останови плейлист и создай план заново; иначе запись блокируется.

## Хранение и таймер

`/littlefs/playlist.bin`: 42 байта настроек + CRC32, всего 46 байт. Firmware 1.4
использует private disk byte 40 для перехода 0–5; legacy USB record оставляет
его нулём. Старый disk файл 1.3 читается как обычная смена. Downgrade на 1.3 при
ненулевом переходе отключит плейлист как неизвестный файл, не удаляя assets.
Запись через
`playlist.tmp`, flush/fsync и atomic rename. Невалидный/отсутствующий файл отключает
режим, сохраняя manifest/assets; stale temporary удаляется при boot.

Tick проверяет CRC сцены, меняет ACTIVE в RAM и использует существующий strip/DMA
renderer. Переключения не записывают manifest/настройки во Flash. Последующая
явная операция manifest может сохранить текущий ACTIVE. Остановка через GUI
сама не сохраняет текущую сцену в manifest: после RESET в выключенном режиме
используется последний записанный ACTIVE. Ручной показ сохраняет его штатно.

Таймер обслуживается основным циклом без отдельного framebuffer/task. Unsigned
elapsed корректен при rollover; upload busy отодвигает tick. Отрисовка и USB
работают в одном firmware loop: при смене картинки возможна короткая задержка.

## Проверки

Python suites/portable smoke проверяют codec/limits, stale identity/CRC,
capability gate, ACK readback, отсутствие повторов при потерянном ACK,
GUI порядок/интервал и сохранность RAM preview.

`tests/playlist_test.c` проверяет missing IDs, upload busy, rollover, сохранение
настроек и повреждённый файл. Подключён к `tools/run_host_tests.py`; native
GCC/Clang на текущей Windows отсутствует, C host suites не выполнены.

Firmware 1.4 build/flash: ESP-IDF 5.5.3, .bin 360384 байта. Native Windows tests:
89 desktop + 8 tools прошли. Extracted portable ZIP smoke включает миниатюры,
клики стрелок, visibility настроек и readback выбранного эффекта.

На COM3 firmware 1.3 все 7 пользовательских assets после прошивки побайтово
совпали с preflash .fclip; названия и порядок сохранены. Таймер переключал ID
2/1/3, free во время ticks оставался 462848 байт (total 2031616). Проверены upload
и delete остановки на собственной временной сцене ID8; она удалена. ACTIVE7 и
выключенный режим восстановлены после диагностик. Пользовательские сцены не
заменялись/не удалялись. Пользователь подтвердил переключение на LCD версии 1.3,
после чего запросил UI правки и переходы. Пользователь подтвердил корректную
работу обновлённого окна (миниатюры, скрытие интервала и кнопки ▲/▼), переходы
на LCD и сохранение выбранного эффекта/плейлиста после аппаратного RESET.
Физическая проверка firmware 1.4 завершена.

Firmware 1.4: все шесть режимов проверены на плате через command 18, readback
эффекта и responsive HELLO/LIST_SCENES после tick. Полная операция сохранения
с чтением обратно заняла 1.140–2.062 секунды (это не чистое время анимации).
Первоначальный вариант с мелкими seek/SPI транзакциями вызвал timeout; заменён
последовательным чтением строк и высокими узкими DMA tiles в тех же 5120 байтах.
После проверки все assets вновь побайтово совпали с preflash архивом; total/free
2031616/462848. Выбранный пользователем плейлист 1/5/7/6, 3 секунды, включён,
обычная смена, восстановлен. Frozen smoke: 14 checks, 0 asset reads, 3.625 секунды.
