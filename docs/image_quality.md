# Качество статичных изображений

Обработка выполняется на desktop в ImageWorker; firmware, protocol v1, static
asset v1 и partition layout не изменяются. GIF сохраняют прежний Bicubic/NEAREST
pipeline независимо от этих настроек.

Рядом с preview доступны Lanczos (по умолчанию) и прежний Bicubic, резкость
0–100 % (по умолчанию 25 %) и необязательный Floyd–Steinberg dithering RGB565.
Порядок: FIT/FILL/масштаб/позиция и уменьшение → прозрачность поверх выбранного
фона → умеренный UnsharpMask → dithering → прежний RGB565 asset v1.
Пиксель-арт использует NEAREST и отключает резкость/dithering; настройки качества
при этом сохраняются для возврата в обычный режим. «Сбросить обработку» возвращает
Lanczos/25 %/без dithering, не меняя положение. Dithering может давать зерно,
резкость — подчёркивать контуры: оба эффекта нужно оценивать в preview.

Preview декодирует точный outgoing RGB565. «До / после…» сравнивает прежний
Bicubic без обработки с текущим результатом при одинаковом положении; zoom
100/200/400/800 % увеличивает пиксели без сглаживания. Окно сравнения — снимок
последнего завершённого render; чтобы сравнить новые настройки, открыть его снова.
Редактор продолжает отображать промежуточные кадры во время drag/wheel, оставляя
одну render-задачу и отбрасывая результаты другого исходника. Запись разрешена
только для последнего завершённого состояния. Обработка не восстанавливает
детали, которых нет на экране 320×172.

Lanczos рассчитывает только видимый прямоугольник источника и выдаёт слой не
больше LCD; огромная масштабированная панорама не создаётся. Исходник ограничен
40 MP. Полупрозрачность обрабатывает RGBA resize Pillow; dithering работает уже
в координатах итогового экрана. Алгоритмы не меняют размер static asset:
320×172 по-прежнему занимает 110104 байта с заголовком.

## Локальные проекты

«Сохранить проект…» явно сохраняет файл `.fclipimage`: ZIP с ровно `source.png`
и `settings.json`; version1 читается, новые version2 включают текстовые слои.
Исходное RGBA после EXIF orientation и параметры
размещения/обработки хранятся отдельно от платы, `.fclip` коллекций, preferences
и автоматического RAM cache. Никакие USB identity, trust или сцены в проект не
добавляются. Запись через временный файл и os.replace сохраняет предыдущий проект
при ошибке. IO и PNG codec выполняются в image worker.

«Открыть проект…» работает offline, восстанавливает настройки и готовит новую
сцену; он не перезаписывает никакой ID на плате. Повторная обработка берёт
сохранённый исходник, а не предыдущий уменьшенный результат. Для сцены, прочитанной
с платы, проект содержит только её RGB565 pixels: исходный PNG/вырезанные области
и исходные детали восстановить невозможно. Это явно экспортируемый файл; перед
закрытием редактора нужно сохранить проект самостоятельно.

Чтение не извлекает ZIP на диск. Проверяются точный набор/число entries, лимиты
64 MiB для файла и распакованных entries, JSON ≤32 KiB, версия/типы/границы
всех настроек и статичный PNG ≤40 MP. Повреждённые или неизвестные проекты дают
явную ошибку с техническими подробностями.

## Проверка

Автотесты проверяют точное соответствие preview/asset, неизменность исходника,
pixel-art и GIF parity, прозрачность/панорамы/offscreen, уменьшение средней
ошибки градиента dithering, сохранение/открытие проекта, отказ от опасных entries
и недопустимых настроек, сохранность предыдущего файла при ошибке commit.
Portable smoke дополнительно проверяет качество, окно сравнения и worker
roundtrip проекта на mock без USB. Проверка на LCD требует подтверждения человека.

На Windows: 148 desktop +9 tools tests прошли; portable ZIP прошёл
SHA256/извлечение/изолированное окружение и 22 bundled smoke checks, без USB.
Замер синтетического RGBA 8000×5000: 1,152 s на полный render с before/after
и dithering; это наблюдение на текущей машине, а не гарантия времени.
Пользователь подтвердил сравнение новой static сцены с LCD и работу проектов.
Для резкости обнаружена проблема штатной стрелки увеличения QSpinBox на Windows;
введены отдельные кнопки ▼/▲, как в плейлисте, с сохранением ввода числом и
границ 0–100 %. Автотест проверяет обе кнопки и границы; пользовательская
проверка исправленной стрелки и новой раскладки подтверждена пользователем.
Прошивка в этой фазе не изменялась.

По пожеланию пользователя приложение запускается maximized. Workspace разделён
на три регулируемые колонки: слева сцены и добавление, в центре preview и блок
действий/памяти/загрузки, справа настройки и локальные проекты на всю высоту.
Сдвиги X/Y расположены рядом; настройки не имеют прежнего ограничения ширины
245 px. На Full HD основные настройки помещаются без прокрутки; на меньшем
окне остаётся вертикальная прокрутка. Полноэкранный режим не скрывает панель
задач Windows: используется обычное развёрнутое окно.
