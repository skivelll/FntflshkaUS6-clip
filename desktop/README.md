# FntflshkaUS6 clip — Desktop MVP

Нативное приложение Windows на Python 3.12 и PySide6. Firmware 1.2 добавляет
названия и порядок сцен к совместимым расширениям USB protocol v1. Asset v1 и Flash layout
не изменены.

## Запуск на Windows

Из корня репозитория, с установленным Python 3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .\desktop
.\.venv\Scripts\python.exe -m fntflshka_us6_clip
```

Если `.venv` уже существует, создавать её заново не нужно. После editable
установки приложение можно запускать из любой папки, в том числе:

```powershell
cd desktop
..\.venv\Scripts\python.exe -m fntflshka_us6_clip
```

Без терминала: открой в Проводнике `.venv\Scripts\fntflshka-clip.exe`.
Это стандартный Python GUI entry point, без консоли; installer/PyInstaller
в этой фазе не используются. Для разработки без платы:

```powershell
.\.venv\Scripts\python.exe -m fntflshka_us6_clip --mock
```

## Пользовательский сценарий

1. Закрой serial monitor и CLI, подключи заколку по USB-C, запусти приложение.
2. Дождись завершения «Загружаю сцены в память» и `clip connected`. Порт определяется автоматически, затем проверяются
   HELLO identity и GET_CAPABILITIES. Конкретный COM не зашит в код.
3. Нажми `+ добавить` или перетащи один PNG/JPG/WEBP в окно.
4. Выбери «Вписать» (FIT) или «Заполнить» (FILL), масштаб, X/Y, фон и при
   необходимости «Пиксель-арт». RGB565-preview — точные пиксели отправляемого
   asset, увеличенные для просмотра. Физические особенности LCD/подсветки
   монитор компьютера не воспроизводит.
5. Проверь размер и память, нажми `ЗАЛИТЬ В ЗАКОЛКУ` и дождись `готово :3`.
   После ACK приложение проверяет запись, checksum, размеры и ACTIVE через
   LIST_SCENES, затем обновляет storage.

Новая сцена получает первый свободный ID 1–8. Существующие сцены не
перезаписываются. После заполнения всех восьми мест загрузка отключается;
можно освободить место кнопкой «Удалить…». Диагностический CLI остаётся
доступен отдельно.

## Управление сценами

Выбери сохранённую сцену слева и нажми «Показать на заколке». Активная сцена
отмечена точкой. Выбор сохраняется при периодическом обновлении списка.
Кнопка «Удалить…» требует подтверждения, по умолчанию отмена. При удалении
активной сцены firmware включает встроенную демонстрацию; остальные сцены
сохраняются. После действия проверяются ACK, LIST_SCENES и актуальная память.
Во время upload/другого действия конфликтующие кнопки заблокированы.

При подключении все сцены заранее читаются с платы, проверяются по CRC и
сохраняются в оперативной памяти до закрытия приложения. Во время начальной
загрузки виден общий progress; окно отвечает и его можно закрыть. Затем выбор
сцены/миниатюры использует кэш и **не делает USB-запросов чтения asset**.
В проверенном сценарии семь сцен загрузились за 46 секунд. Переименование,
порядок, включение и переподключение той же платы не перечитывают картинки.
Изменённые/новые assets обновляются отдельно; загруженный через GUI asset сразу
попадает в кэш. Удалённые сцены исключаются. Другая USB identity очищает кэш.
Настройки и upload относятся к новой картинке; для возврата к ней выбери строку
с именем файла или добавь картинку.
На firmware 1.0 включение/удаление работают, а preview сообщает о необходимости
обновления — неизвестная команда не отправляется.
С firmware 1.2 кнопка «Имя…» сохраняет название на заколке: до 48 байт UTF-8,
включая кириллицу. Пустое имя возвращает подпись «Сцена N». Кнопки «↑ Выше» и
«↓ Ниже» сохраняют порядок на устройстве. Это организация списка, не слайд-шоу.
Старые сцены без названия читаются с прежним ID. На старой firmware команды
имен/порядка не отправляются; соответствующие кнопки недоступны.

«Заменить картинку…» выбирает новый исходник для выбранного ID. Настрой его и
нажми «ЗАМЕНИТЬ СЦЕНУ N», затем подтверди действие. Имя и порядок сохраняются,
новый ID не создаётся; остаётся безопасный A/B commit. Изменившийся между выбором
и загрузкой checksum отклоняется. Запас памяти нужен под новый файл рядом со
старым, поэтому замена может требовать свободного места даже при одинаковом размере.

Размер asset точен: `24 + width × height × 2`, для 320×172 это 110104 байта.
Проверка памяти учитывает 8192 байта запаса, требуемого firmware. «После вычета
файла» — точное арифметическое вычитание размера файла, не обещание конечного
free LittleFS: блоки и metadata дополнительно расходуют память. Реальный остаток
запрашивается после загрузки.

## USB recovery

Если ранее успешно идентифицированная заколка перестала отвечать, worker
пробует обычное переподключение. Recovery RTS/DTR разрешён только при совпадении
порта, VID/PID и непустого USB serial number с уже проверенным устройством в
текущем сеансе приложения. Чужая identity отзывает доверие; неизвестные порты
никогда не сбрасываются. Recovery ограничен одним разом за 30 секунд для
каждого устройства и записывается в журнал.

Если приложение впервые запущено уже после проблемного аппаратного RESET,
надёжной предыдущей identity ещё нет: переподключи USB-кабель. Никакого
автоматического RESET ради тестирования или нового upload приложение не делает.

При обрыве upload автоматического повтора нет. Старую сцену защищает firmware
A/B commit. Если следующая попытка сообщает незавершённую загрузку,
переподключи USB: временная запись очищается firmware при загрузке.

## Архитектура

- `core/`: общие Qt-независимые asset codec, framing, identity, serial transport
  и reset sequence. CLI `tools/clipctl.py`/`tools/make_asset.py` используют эти же
  модули; direct CLI работает и без editable установки.
- `device/`: typed capabilities/snapshots, инъекция transport, discovery,
  recovery, проверяемый upload и протокольный mock (ACK/NO_SPACE/disconnect).
  Общий DeviceClient также используется CLI для upload/list/capabilities.
- `media/`: безопасный статичный импорт с EXIF orientation, affine FIT/FILL,
  ограниченный масштаб, alpha compositing и RGB565-preview из asset payload.
  Affine rendering не выделяет огромный промежуточный framebuffer для панорам.
- `scenes/`: scene records, выбор свободного ID и оценка storage.
- `ui/`: окно, preview и настройки; `resources/theme.qss` — базовая тема.
- Один `QThread` обслуживает serial последовательно; другой готовит картинки.
  Debounce и generation ID отбрасывают устаревший preview, очередь render
  ограничена одной текущей задачей. UI не ждёт serial/конвертацию синхронно.

Журналы с ротацией находятся в Windows user-data directory, обычно
`%LOCALAPPDATA%\FntflshkaUS6\FntflshkaUS6 clip\logs\clip.log`.
Точный путь показан в раскрывающемся блоке «Устройство и журнал».
Traceback остаётся в журнале; каждый chunk в обычном режиме не логируется.

## Зависимости и tests

Отдельные desktop runtime dependencies: PySide6 6.10.3, Pillow 12.3.0,
pyserial 3.5. PlatformIO/ESP-IDF для запуска приложения не требуются.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s desktop/tests -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip check
```

Большинство tests не требуют платы. Qt smoke/integration tests открывают
настоящие окна и используют mock; real-device upload не входит в автоматический
suite. Он проверяется отдельно с визуальным подтверждением LCD.

Ограничения: только статичные PNG/JPEG/WEBP, не более 40 MP; анимированные
WEBP/APNG отклоняются. Только protocol/asset v1, RGB565 и геометрия до 320×172,
как разрешено asset v1. Реальные меньшие размеры берутся из capabilities.
Нет slideshow, installer, GIF, fonts или wireless функций. Текущая firmware 1.2
читает старые manifests; автоматический downgrade на firmware с меньшим лимитом
размера manifest не предусмотрен (см. docs/usb_protocol.md).
